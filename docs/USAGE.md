# 使用教程（0.13.0 起）

普通用户使用模型 API，只需**下载安装包 → 浏览器加载 → 填写自己的 Key**。不需要运行代码或启动本机服务。

## 安装浏览器扩展

1. [下载 `x-comment-assistant.zip`](https://github.com/captainyufei/x-comment-assistant/releases/latest/download/x-comment-assistant.zip)。不要选择 GitHub 的源码 ZIP。
2. 完整解压到一个长期保留的目录。解压后 `XCommentAssistant/` 内直接有 `manifest.json`。
3. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
4. 开启「开发者模式」，点「加载已解压的扩展」，选择 `XCommentAssistant` 文件夹。
5. 在工具栏拼图菜单中找到「X 评论助手」，固定图标方便使用。

不要选择 ZIP 文件，也不要选 `icons/` 等子文件夹。加载后不要删除或移动 `XCommentAssistant`，浏览器仍需读取它。

安装 ZIP 同时用于 Chrome 和 Edge。当前没有扩展商店安装入口；主要验收环境为 macOS，Windows 实机尚待验证。

## 配置模型 API

打开工具栏「X 评论助手」→「模型设置」→「模型 API」。默认使用**浏览器直连**。

1. 选择你有 API 额度的服务商，填它自己的 API Key。
2. 点击输入框外，或点「刷新列表」，等模型列表返回。新服务商未填 Key 时，模型名称为空。
3. 明确选择一个可以聊天生成的型号。模型列表来自服务商，列表出现不等于有生成权限、余额或视觉能力。
4. MiniMax／豆包目前需选「手动填写模型名称…」，填写服务商控制台里的型号或接入点 ID。
5. 点「保存配置」。首页「模型已配置，生成时验证」只表示配置保存成功，第一次生成才验证真实调用。

默认地址是服务商的官方地址。千问、Kimi 等使用不同地域的 Key 时，在「服务地址」中选择实际对应的官方地址；不要填入不明转发服务。

Key 留空只沿用**同一服务商**已经保存的 Key；换服务商时需填写它自己的 Key。留空不表示删除 Key。不要把 Key 粘贴到 GitHub Issue。

云服务使用你自己的账户和余额，模型 API 费用不由本插件支付。

## 每次如何回复

1. 在 X 上找到原帖，点击它的「回复」，确认回复对象正确。
2. 点「X 评论助手」卡片中的「生成四条回复」。打开回复框或选择风格不会自动调用模型。
3. 阅读四条候选，点某条「填入」，或点「复制」后粘贴。已有草稿时按提示决定替换或追加。
4. 自己修改内容并检查事实，最后点击 X 的「回复」。**本插件不自动发送。**

自动匹配会按原帖语境为四条选择风格；手动选择则生成四条同风格回复。风格修改只影响下一次生成；「换一组」会再发起一次请求。

小窗只负责设置，候选显示在 X 原帖的回复框旁。普通发帖窗口没有原帖对象，不能作为回复生成入口。如果同时安装了其他 AI 扩展，请认准「X 评论助手」，不要混淆其他扩展的「AI Generate」按钮。

## 本地模型（可选）

本地模型连接也不需要本项目的 Node 桥接，但你需要已经安装相应软件、加载模型并启动其 API 服务。

| 服务 | 默认本机服务地址 |
| --- | --- |
| Ollama | `http://127.0.0.1:11434/v1` |
| LM Studio | `http://127.0.0.1:1234/v1` |

在「模型设置」→「本地模型」选择服务，填写实际地址，刷新模型列表，选择模型后保存。端口被改过时填实际值；当前只接受本机回环 HTTP `/v1` 地址。

本地服务未开启认证时 Key 可留空。插件不负责下载或加载模型，也不会因为模型在本机运行就假定它支持图片。

## 本地 Agent（可选）

浏览器不能直接启动电脑里的 Codex／Claude Code。只有选择这种方式，才需另装本机桥接、配置当前浏览器扩展 ID，并复用自己已经登录的 CLI。

具体步骤见 [本地 Agent 与桥接说明](LOCAL_AGENT.md)。只使用 API 或已运行本地模型服务的用户，可以忽略该文档。

## 图片、视频与回复质量

只有已明确适配视觉能力的具体 API 型号才会读取受限公开图片，其他型号使用文字和替代文字。视频目前最多读封面，没有连续画面、音频或字幕。

关键图片、对白或前文缺失时，不应期待模型猜对整个梗。当前没有实时联网检索，近期事实、专业结论和情绪判断都需要自己核对。格式检查通过不代表含义一定正确。

## Key 保存在哪里

浏览器直连的 Key 使用 AES-256-GCM 加密：密文保存在扩展的 `chrome.storage.local`，不可导出的加密密钥保存在扩展自己的 IndexedDB，不走浏览器同步。

它不是系统钥匙串。加密不能保证抵御已经被控制的浏览器、扩展代码或用户资料。更换浏览器、清除扩展数据、删除扩展或换设备后，应准备重新填写自己的 Key。不要分享整个浏览器资料目录。

模型调用直接向所选服务商发送认证及当前原帖所需的内容。读取模型列表时，也会使用该服务商的 Key；未点击保存的输入不写入持久设置。

## 更新与卸载

### 更新用户安装包

1. 等当前生成结束，下载新的 [用户 ZIP](https://github.com/captainyufei/x-comment-assistant/releases/latest/download/x-comment-assistant.zip)。
2. 解压后，用新版文件更新**原来加载的 `XCommentAssistant` 文件夹**。保持原路径，不要先移除扩展。
3. 在 Chrome／Edge 的扩展页对「X 评论助手」点「重新加载」。
4. 刷新 X 页面，再生成一次确认。

配置和加密 Key 保存在浏览器中，不在安装 ZIP 内。保持原路径和原浏览器资料，可避免因新扩展身份而重新配置；换路径、浏览器或资料可能需要重新填写 Key。

### 从旧版升级

旧版已经配过本机桥接的用户会保留桥接方式，避免把原有配置打断。若想改用无需服务的浏览器模式：

1. 更新扩展并刷新 X。
2. 打开「模型设置」底部「高级：连接方式」，选择「浏览器直连（推荐）」。
3. 重新填一次自己选定服务商的 Key，选择模型并保存。

**旧桥接 Key 不会自动复制到浏览器**，两种方式分别保存。切换方式不会删除另一侧配置；有正在生成的任务时先等完成或停止，再切换。

确认浏览器直连正常后，可按 [桥接文档](LOCAL_AGENT.md#停止与卸载桥接) 停掉自己曾安装的本机服务。普通新用户没有这一步。

### 卸载

在 Chrome／Edge 的扩展管理页移除「X 评论助手」，再删除解压目录。移除扩展会清除其浏览器本地配置和密钥数据；重装时需重新填写。

如果另装过本机桥接，移除浏览器扩展不会替你停止它，也不会替你清理桥接自己的配置。按 [桥接文档](LOCAL_AGENT.md#停止与卸载桥接) 单独处理。

## 排查问题

| 现象 | 先检查 |
| --- | --- |
| 找不到扩展的 `manifest.json` | 确认下载发行安装包，解压后选中 `XCommentAssistant`，不要直接选 ZIP |
| 本插件没有出现在 X 回复框 | 已启用扩展、允许访问 X、刷新了 X，且从原帖点了「回复」 |
| 首页「尚未配置模型」 | 选择服务商、填自己的 Key、选模型并保存 |
| 首页仍显示本机服务未连接 | 旧桥接方式仍启用；可在高级设置切到浏览器直连，再填 Key |
| 读取模型失败 | 检查 Key、网络和官方服务地址；MiniMax／豆包手填型号 |
| API 认证／余额／限流错误 | 检查服务商控制台；列表读取成功也不保证能生成 |
| 本地模型连不上 | 先启动 Ollama／LM Studio 的 API 服务，检查端口和模型已加载 |
| 生成被取消或超时 | 检查网络和模型状态，再主动点击重试；不自动切换型号或反复重试 |
| 候选未填入 | 检查草稿替换确认，也可「复制」后手动粘贴 |
| 升级后界面没变化 | 对插件点「重新加载」，再刷新 X；只更新磁盘文件不够 |

报告问题时提供插件版本、系统、浏览器、连接方式、服务商与型号、复现步骤和脱敏错误截图。不要上传 Key、浏览器资料或个人草稿。

## 验收边界

当前主要实测环境是 macOS。Chrome／Edge 使用同一用户包；Windows 仍需要实机验收。离线测试、打包检查、真实 API 调用和真实浏览器操作是不同层次的验证，不互相替代。
